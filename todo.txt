Technical Challenge: Improving Semantic Classification and Evidence Validation
1. Multi-condition semantic classification

Currently, the classifier appears to rely heavily on semantic similarity between the document content and the user query.

Explore how to evaluate multiple conditions independently before assigning a final classification.

For example, a document may need to satisfy three conditions:

The correct target entity must be present.

The document must describe the specific activity requested.

The activity must be performed in the specified experimental system.

The final classification should be positive only when the required conditions are sufficiently supported by the available evidence.

2. Context-aware classification

Improve the classifier so that it can distinguish between:

A document that actually performs the requested activity.

A document that merely mentions the entity.

A document that discusses a related but different activity.

A document that does not provide sufficient information to make a decision.

Consider introducing a third classification, insufficient_evidence, instead of forcing every document into a binary decision.

3. Evidence validation

Every classification must be supported by an actual sentence extracted from the source document.

The system should:

Avoid using publication titles as experimental evidence.

Verify that the selected sentence supports the classification.

Avoid generating or modifying sentences presented as source evidence.

Return an appropriate uncertainty status when supporting evidence cannot be identified.

4. Confidence and ranking improvements

Investigate whether the current confidence-scoring approach reliably reflects classification quality.

Explain how you would distinguish semantic similarity scores from actual classification probabilities and how you would validate confidence calibration.

5. Model evaluation

Precision, recall, and F1-score.

Examples of incorrectly classified documents and how they were addressed.
